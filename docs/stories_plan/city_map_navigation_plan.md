> **第 1 章教玩家怎樣在東京移動；第 2 章才讓玩家決定下一步要去哪裡。**

## 1. 玩法梯度

### 1.1 Chapter 1：線性導航

Chapter 1 的地圖不是策略選擇，而是空間 onboarding。玩家要學會：

- 地圖是跨章常駐的城市介面，不是 Chapter 2 突然出現的新系統。
- 地點有固定位置與固定身份。
- 同一地點可以在新證據出現後重新開放，意義會改變，但地理位置不變。
- 點擊圖釘代表「前往已確認的下一個場所」，不是選擇劇情分支。

每次打開地圖時：

1. 畫面顯示目前已建立的城市輪廓。
2. 唯一目的地亮起並取得焦點。
3. 玩家查看簡短目的說明。
4. 玩家選取圖釘後直接前往，不再出現第二層確認。
5. 不消耗時間、金錢、行動點或其他資源。

推薦 UI 文案：

- `新的調查地點已確認`
- `前往下一個地點`
- `前往：雨鐘咖啡館`

禁止使用：

- `選擇下一個調查地點`
- `你要先去哪裡？`
- `剩餘行動次數`

### 1.2 Chapter 2：自由調查

Chapter 2 不重教「如何打開地圖／如何點圖釘」。它只教 Chapter 1 沒有出現的新規則：

- 同一階段可以有多個可前往地點。
- 地圖會隨 Phase A／B／C 擴張。
- 玩家可改變地點調查順序，但不能改變案件的 proof order。
- 可選內容與主線內容必須清楚區分；支線不能藏唯一必要證物。

Chapter 2 現有三階段澀谷箱庭、四塊證據板與七段審查會 proof order 保持不變。

## 2. 城市布局的最低固定範圍

本次不一次設計完整東京開放世界，但從第一章開始必須固定以下廣域錨點的相對位置：

```text
吉祥寺案件區 ─── 相馬事務所／中央據點 ─── KAGAMI 審查設施
                         │
                       澀谷
```

這是敘事拓撲，不要求真實比例。後續美術可以增加鐵路、河道、行政區與更多章節區域，但不能改變既有錨點的相對方向。

### 2.1 Chapter 1 固定地點身份

| 地點 | 故事身份 | 重複使用 |
|---|---|---|
| 相馬偵探事務所 | 全篇主基地；委託、資料整理與章末私人鉤子 | Chapter 1 開場與章末返回使用同一節點 |
| 雨鐘咖啡館 | 主案現場、反轉重查與結案回訪 | 三次開放都沿用同一節點 |
| 警署臨時會面室 | 三宅詢問場所 | Chapter 1 單次主線目的地 |
| KAGAMI 證據摘要審查室 | 第一輪失敗與最終審查 | 兩次開放都沿用同一節點 |
| 吉祥寺商店街 | 第一輪審查後的主線證據重排場所 | 不是支線 hub |
| 外包資料審查分室 | 北見外包權限、工單與身份收束場所 | Chapter 1 後段主線目的地 |
| 澀谷 | Chapter 2 主案件區域 | Chapter 1 可保留為未揭露輪廓，不顯示可選圖釘 |

具體街道地址、步行分鐘與行政區細節可在地圖美術定案時補充；節點 ID、名稱與相對位置一旦進入 playable content 就不得任意更改。

## 4. Chapter 1 無支線契約

Chapter 1 不建立任何支線任務系統。現有 plan 中被稱為「角色微支線」「可選」的材料，需按以下規則理解。

### 4.1 保留為主線內嵌人物節拍

| 內容 | 定位 |
|---|---|
| 相馬壞掉的咖啡機 | 事務所線性人物演出 |
| 早坂紙本收據 | 主線場景中的短人物動作 |
| 三宅的蛋糕與熱牛奶 | 解釋主案小謊的必要人物材料 |
| 店長捨不得丟的舊掛鐘 | 主案物理錨點與人物細節 |
| 神谷便利貼 | 審查會走廊的短人物演出 |
| 北見折痕名片 | 北見焦慮與早期弱曝光 |
| 黑瀨觀察鞋底／水痕 | 一句現場反應，不建立任務 |

這些內容：

- 不產生任務卡。
- 不產生額外圖釘。
- 不提供獨立獎勵。
- 不影響證物是否可取得。
- 不建立可錯過的審查會分支。

### 4.2 移除或降為無追蹤環境文字

- 片瀨的末班車時間錯覺不建立獨立調查鏈。
- 增田集點卡不建立收集或回報流程。
- 藍色透明傘不可被做成可追查支線；它仍只是公開影像可回挖的背景伏筆。
- 任何與青葉、`ZW_A16.lock` 或雨宮身份有關的額外探索不得在 Chapter 1 變成可選任務。

文件用語應優先使用：

- `線性人物節拍`
- `主線內嵌人物細節`
- `環境演出`

避免使用 `支線`，以免 scene writer、designer 或 implementation agent 誤建任務與分支。

## 5. 地圖狀態與敘事規則

Chapter 1 只需要三種玩家可理解的狀態：

| 狀態 | 玩家看到 | 互動 |
|---|---|---|
| 可前往 | 唯一目的地高亮；顯示本次目的 | 可選 |
| 已到訪 | 可保留低對比圖釘，建立空間記憶 | 不可選 |
| 未揭露 | 不顯示圖釘與名稱 | 不可選 |

硬規則：

1. 畫面上任何時刻最多只有一個可互動圖釘。
2. 已到訪圖釘不得因 disabled 狀態仍接受滑鼠、鍵盤或手掣事件。
3. 未揭露地點不得透過 DOM label、輔助文字或焦點順序洩漏。
4. 同一節點重新開放時沿用相同位置，改為可互動並更新目的文案。
5. 點擊唯一目的地後直接進入下一段，沒有錯誤選擇與返回確認。
6. Save／Continue 要回到目前地圖步驟或已進入的下一場景，不可重複觸發一次性故事 reveal。

## 6. Chapter 2 同步修正

Chapter 2 現有案件內容保持不變，只調整 onboarding 定位。

### 6.1 新定位

> 玩家已在 Chapter 1 學會打開地圖、閱讀目的地、點選圖釘與辨識已到訪地點。Chapter 2 第一次同時開放多個目的地，要求玩家自行決定調查順序。

### 6.2 Chapter 2 不再教授

- 如何打開地圖。
- 如何選取圖釘。
- 如何查看目的說明。

- 已到訪與可前往圖釘的基本視覺差異。

### 6.3 Chapter 2 新教授內容

- 多個可前往地點同時存在。
- Phase A／B／C 的地圖擴張。
- 主線與可選節點的標示差異。

- 支線不藏唯一必要定錘。

Chapter 2 的首個「粉絲手機其實拍到直播牆」翻面、四塊證據板、青葉公開資料核驗與蓮見 proof order 全部不受本次修改影響。

## 7. Chapter 1 scene authoring 影響

目前 Chapter 1 playable content 由多個 linear、investigation、analysis 與 interrogation scene 順序串接。地圖必須作為既有 scene 之間的主線轉場，不得把所有內容硬合併成一個大型 investigation scene。

Authoring pass 應：

- 在九個跨場所邊界插入 map-navigation interstitial。
- 保留原 scene 的對話、證物 reveal、story fact、objective 與 authorization 邏輯。
- 若一個既有 linear scene 內同時包含兩個不同場所（例如結案回訪後返回事務所），可在自然轉場點拆成兩個 scene，僅為插入地圖；不重寫內容。
- 地圖 interstitial 不收集證物、不斷言 story fact、不解鎖額外問題、不承擔案件推理。
- 地圖只負責呈現目的、接受唯一地點選取並進入下一個既有 scene。

## 8. 非目標

本次 story／code handoff 不包含：

- Chapter 1 自由調查。
- Chapter 1 支線任務。
- 行動點、交通費、時間流逝或錯過事件。
- NPC 日程或城市模擬。
- 可操作列車／步行／道路選擇。
- 地圖完成率、收集物或成就。
- 隱藏路線與秘密圖釘。
- 全東京精確 GIS／鐵路比例。
- 地圖編輯器。
- 路徑搜尋、連線動畫或地區解鎖樹。
- 為 Chapter 1 建立獨立於現有 scene／story state 的持久進度模型。

## 9. Story Acceptance Criteria

本計劃完成實作後，故事層應滿足：

- [ ] Chapter 1 九次主要跨場所移動都由玩家在地圖上觸發。
- [ ] 每次地圖恰好只有一個可互動目的地。
- [ ] Chapter 1 沒有支線任務、支線圖釘或可錯過主線材料。
- [ ] 雨鐘、KAGAMI 審查室與相馬事務所重複出現時沿用同一節點與位置。
- [ ] 地圖轉場不改變任何證物取得、story reveal、程序授權或 proof order。
- [ ] Chapter 1 仍維持原定 2.5～3 小時級別，不因地圖加入重複長對話。
- [ ] Chapter 2 明確成為第一次多目的地自由調查，而不是第一次使用地圖。
- [ ] Chapter 2 既有 Phase A／B／C、支線邊界、四塊證據板與兇案 proof order 保持不變。
- [ ] 未來章節沿用同一城市拓撲時，不移動已建立的廣域錨點。

## 10. Code Handoff 原則

程式實作應以最小擴張為原則：

- 重用現有 investigation navigation、sublocation lock／visibility 與 `enter_sublocation` 命令。
- 地圖只新增 presentation metadata 與 UI；不建立第二份 durable navigation state。
- Chapter 1 map-navigation interstitial 只需支援一個可用目的地，但資料與元件不可把「只能一個」寫死，Chapter 2 要能沿用同一表示法呈現多個可用目的地。
- 沒有地圖 metadata 的既有 investigation scene 沿用目前地點導航，不受影響。
- 第一個 code slice 只交付 Chapter 1 真實路線與 Chapter 2 可重用 contract；不建立通用世界地圖框架或 editor。
