本章真正的三根推理承重梁只有：

1. **牆不是箱。**
2. **composite 不是 raw。**
3. **十五分鐘通行碼讓路，但能濫用它的人不是三枝。**

青葉公開資料核驗是跨章承重點，不是第四根直播案承重梁。

## 1. 本章一句話方向

相馬律在數萬人都「看見」如月真白沒有離開的澀谷直播現場，拆開直播牆、贊助投影、後台合成畫面、個人裝置去向、十五分鐘維修通行碼與服務梯異常，找出她真正被帶離玻璃箱的路線；最後證明殺死她的不是最可憎的競爭直播主，而是最懂她安全流程、帳務壓力與沉默方式的經紀人蓮見透。

本章前台問題：

> **誰真正看到了什麼？**

本章情緒核心：

> 一個靠被觀看維生的人，最後被「所有人都看見了」這件事吞掉。

本章方法論升級：

> 第 1 章問「這筆紀錄到底記了什麼？」  
> 第 2 章問「這個人站在哪裡，又透過什麼看見？」

## 3. 案件真相

### 3.1 蓮見的犯罪意圖

蓮見預謀的是：

- 把真白從公開視線中隔離。
- 利用合法 sponsor maintenance request 取得十五分鐘通行碼。
- 把第一反應壓成技術事故／安全確認。
- 在空置樓層逼她撤回退出公司與帳目公開。

他沒有預先準備專用殺人工具。

殺意真正升級的瞬間是：

> 真白告訴他，帳目對照已交給外部會計師，直播結束後備用帳號會自動發聲明，而蓮見沒有權限撤掉。

對蓮見而言，最重要的不是金錢本身，而是他一直能「替真白說話、替她取消、替她解釋」。這一次，那個控制入口完全失效。

### 3.2 實際犯罪流程

1. 開播前 briefing 公開說明：Silent Visual Challenge 中若有安全異常，主播不得臨時對外講安全流程，而是前往背面安全位，由導播／經紀人補場。
2. 真白手機在直播開始後留在箱內資料座。
3. 蓮見透過贊助商窗口送出合法「投影設備短暫校準」申請。
4. 系統生成 **00:00～00:15** 的十五分鐘通行碼，讓服務艙口、Sponsor Corridor、M-03、服務梯 B 與巡邏表暫時顯示合法維修。
5. 00:00 / `S+00m00s`，正面 sponsor projection 啟動，觀眾被主持人與主螢幕引導。
6. `S+00m30s～S+02m00s`，Silent Visual Challenge 開始；這段本來就不期待真白自由互動。
7. `S+00m45s～S+01m30s`，蓮見用耳麥流程通道通知「正面投影溫度異常」，要求真白到背面安全位。
8. 真白依已 briefing 的流程離箱；手機仍留在資料座。
9. 箱內只剩半透明投影輪廓板、椅背、字幕、燈影與贊助畫面。
10. `S+02m00s～S+03m00s`，預錄贊助旁白與投影補場撐住前場。
11. 約 00:03，控制室開始發現真人沒有恢復互動，但先進入四步誤判鏈。
12. 00:06～00:15，蓮見帶真白經 Sponsor Corridor、M-03、服務梯 B 到空置樓層。
13. 00:15～00:25，前場才升級為「失聯」，但第一封鎖時機已錯過。
14. 真白在空置樓層明確說出帳目已外送與聲明不可撤回。
15. 蓮見控制崩塌，使用現場掛繩／束線掛帶勒殺真白。
16. 他不再移屍：此時通行碼已失效，第二次搬運只會暴露在公共走廊、低解析 CCTV 與後勤出口。
17. 蓮見改走避難梯／後勤出口回前場，繼續扮演「最冷靜、最有用的經紀人」。
18. 服務梯 B 超時停靠或消防門未回彈被先當成 sponsor maintenance 的物流異常。
19. 約 02:30，樓宇管理因異常未復歸派保全查看，發現屍體。

## 4. Sponsor Mode 與控制室反應鏈

### 4.1 固定 sponsor format

| Sponsor offset | 真實鐘點 | 前場格式 | 真實用途 |
|---|---|---|---|
| `S+00m00s～00m30s` | 00:00:00～00:00:30 | 倒數、燈光下降、正面投影啟動 | 吸走觀眾視線 |
| `S+00m30s～02m00s` | 00:00:30～00:02:00 | Silent Visual Challenge | 真白被安全流程引導離箱 |
| `S+02m00s～03m00s` | 00:02:00～00:03:00 | 預錄旁白、字幕、投影補場 | 真白已進服務核心 |
| `S+03m00s` 後 | 00:03 後 | 理論上恢復真人反應 | 控制室誤判鏈開始 |

### 4.2 控制室四步誤判

| 時間 | 人員 | 合理但錯誤的判斷 | 後果 |
|---|---|---|---|
| 約 00:03 | 導播 | 前面板投影掉層／同步異常 | 未立即喊失蹤 |
| 00:03～00:04 | AD | call back standby；蓮見回覆「人在背面安全位，我去接」 | 以為仍在安全流程 |
| 00:04～00:06 | PR | valid request ID + sponsor 異常 | 先準備技術異常公告 |
| 00:06～00:10 | 保全 | request ID 仍綠色，未收到失聯標記 | 不封 M-03／服務梯 B |

可調查材料：

- 事故通訊 log。
- back-standby 回覆紀錄。
- PR 技術異常模板時間戳。
- 保全 request ID 狀態。

這些證據初期反而支持「當時合理分類為技術問題」，後期才翻成蓮見如何利用流程。

## 7. 半開放調查地圖

### 7.1 Phase A：公開現場

首批開放：

- 透明玻璃箱廣場。
- 巨大直播牆下。
- 後台控制室外圍。
- 粉絲應援區。
- 警方臨時審查車。

Phase A 末／第一輪審查會前再導入：

- 三枝直播工作室。

首個小翻面必須在自由調查開始約 20 分鐘內出現：

> 粉絲堅稱「我親眼拍到真白」，玩家標出拍攝位置後發現最清楚的「真白」其實是直播牆、投影與玻璃反光疊影。

此時只證明：

> **「我親眼看見」不等於「我看見箱內本人」。**

不證明真白已離箱，也不指向蓮見。

### 7.2 Phase B：城市視線

第一輪審查會失利後解鎖：

- 外送員取餐點／小巷。
- 行人天橋。
- 便利店／自動販賣機前。
- 流出影片留言串。
- 商業大樓外側。
- 後台控制室深處。

Phase B 目標：完成「視線板」與「畫面板」。

玩家心理：

> 站在直播牆下看，真白還在。  
> 站在側面看，輪廓不對。  
> 站在控制室看，畫面又不是 raw。

### 7.3 Phase C：維修路線與人物收束

完成視線板與畫面板後解鎖：

- Sponsor Corridor。
- 商業大樓管理室。
- 服務梯 B／服務核心。
- 空置樓層。
- 真白工作室／房間。
- 蓮見事務所。

Phase C 目標：

1. 完成「路線板」。
2. 完成「人物板」。
3. 在真白工作室完成**強制青葉公開資料核驗**。

青葉核驗不是第五塊兇案證據板。

## 8. 四塊兇案證據板

### 8.1 視線板

核心問題：**案發時，誰看見玻璃箱本身？**

必填：

- 現場視線圖。
- sponsor mode 口播／看板。
- 粉絲手機反光。
- 側面裸眼異常。
- 投影輪廓板。

完成結論：

> 群眾沒有集體說謊；他們只是被安排去看同一面牆。

### 8.2 畫面板

核心問題：**平台與保全看到的是原始現場嗎？**

必填：

- `Program Composite` 標籤。
- 平台保存規則。
- sponsor mode 音訊路由。
- 箱內手機資料座。
- 工作人員流出短片。

完成結論：

> 影像是真的，但不是那一刻箱內的直接觀測。

### 8.3 路線板

核心問題：**真白離開箱後去了哪裡？**

必填：

- safety protocol。
- 臨時場地後勤配置板。
- 十五分鐘通行碼。
- M-03 門磁。
- 服務梯 B 超時。
- 消防門未回彈。
- 手錶模糊 ping。
- 空置樓層痕跡。

完成結論：

> 真白不是從直播裡消失；她被一條看似合法的維修路線帶走。

### 8.4 人物板

核心問題：**誰能濫用這條路，又有理由今晚動手？**

必填：

- 蓮見贊助窗口權限。
- 耳麥流程入口。
- 真白收益對照表。
- 退出公司訊息。
- 備用帳號排程聲明。
- 蓮見第一回報／技術事故分類。
- 三枝缺少維修權限的資料。

完成結論：

> 三枝有惡意；蓮見有入口、路線、動機和控制權。

## 9. 青葉公開資料小推理——只建立問題，不解答舊案

這是 Phase C **主線必經、約 5～8 分鐘**的短調查。

### 9.1 玩家比較的兩份公開材料

| 材料 | 表面呈現 | 可證明 |
|---|---|---|
| 網路流傳截圖／短片縮圖 | 「2016 青葉火災當晚畫面」「唯一逃生影像」；來源欄被裁掉 | 大眾長期把它當當夜現場紀錄 |
| 官方資料庫完整頁／公共廣播存檔 | 同一畫面未裁切；頁腳標示「火災後製作」「依證詞與平面資料重構」「官方再現映像」 | 這是事後官方重演，不是當夜 raw |

推薦頁腳：

```text
制作：2016年11月
分類：証言・図面に基づく公式再現映像
用途：公判説明／安全教育資料
```

玩家圈出的不是畫面內容，而是：

- 製作日期。
- 來源標示。
- 「官方再現映像」分類。

### 9.2 當場能證明

- 大眾熟悉的青葉畫面不是當夜原始影像。
- 它是在火災後依據證詞、平面圖與官方材料製作的重演。
- 真白已注意到「公共記憶」與「原始來源」之間的落差。

### 9.3 當場不能證明

- 官方重演內容是假的。
- 重演採用了誰的視角。
- 左側／右側哪條路才是真實。
- 相馬與青葉有何關係。
- `ZW_A16.lock`、A-90、久遠或鏡原與重演有何關係。

### 9.4 持續性未解事項

完成後新增：**「未解事項：青葉官方重演」**。

固定最後一問：

> **當年的官方故事，是根據現場重建的，還是現場被重建成了那個故事？**

### 9.5 青葉動機假說必須降級

玩家自然會問：

> 真白是不是因為查青葉才被殺？

最多用 2～3 分鐘檢查並降級：

- 蓮見確實想取消青葉專題，但他也取消所有不受自己控制的題材、行程與發言。
- 案發當夜蓮見沒有打開、複製、刪除或轉移青葉資料夾。
- 沒有主線黑幕聯絡。
- 作案入口、時間壓力與失控觸發，完全由收益侵吞、退出公司、外部會計師與備用聲明成立。

結論：

> 青葉專題是蓮見想壓掉的其中一個聲音，不是本案幕後委託。

## 17. 最終邏輯自審

### 17.1 為什麼數萬人沒看見真白離開？

不是因為所有人瞎了，而是 sponsor mode 已公開把主視線導到巨大直播牆；前 90 秒本來也不期待自由互動。少數側面視角確實看見異常，只是當時沒有能力解釋。

### 17.2 為什麼真白會自己離箱？

她不是信一句臨時謊話，而是執行已 briefing 的安全流程；蓮見利用的是她對長期工作流程與經紀人的正常信任。

### 17.3 為什麼控制室沒有立刻封鎖？

每個部門只看見職責內的一小塊：導播先查投影、AD 等安全位回覆、PR 壓技術事故、保全看綠色 request ID。蓮見只需要卡在第一回報位置，不需要控制整個系統。

### 17.4 為什麼沒有其他鏡頭直接破案？

鏡頭並非不存在；它們分別是 composite、短時 raw buffer、低幀率 QA、禁止拍後台的 press camera、低解析公共 CCTV。它們能補路線，不能單獨提供完整真相。

### 17.5 為什麼蓮見不移屍？

第一次移動有 sponsor mode、安全流程、十五分鐘通行碼與技術事故分類掩護；殺害後這些掩護都過期。再次搬屍風險大幅上升，他選擇回到最擅長控制的前場。

### 17.6 青葉會不會搶走本章案件？

不會。青葉核驗只證明一個來源事實，約 5～8 分鐘、不新增地點、不進兇案 evidence board、不進審查會。直播案仍能完全不依賴青葉而定罪蓮見。

### 17.7 是否過早暴露終章？

不會。第一幕只完成三件事：

- Chapter 1 說出「青葉」名字並顯示相馬迴避。
- Chapter 2 證明公共記憶依賴官方重演。
- 玩家開始問重演的來源。

仍未揭露：相馬證詞、左右路線、`A16` 解碼、久遠、第零證人、A-90 Hold 或鏡原。

## 19. Chapter 1 → Chapter 2 城市地圖延續契約（2026-08-30 Canon Update）

> 本節直接更新現有 Final Plan，不建立平行的城市地圖計劃。若本節與第 7、11、18 節中「第一次使用地圖」或 onboarding 語意衝突，以本節為準；案件真相、Phase A／B／C 地點、四塊證據板與七段審查會 proof order 全部保持不變。

### 19.1 Chapter 2 不再第一次教授地圖基本操作

玩家已在 Chapter 1 的九次線性跨場所移動中學會：

- 地圖是全篇常駐的東京導航介面。
- 圖釘代表已被劇情確認的目的地。
- 同一地點重新開放時沿用相同名稱與位置，只改變本次目的。
- 如何閱讀目的說明、取得焦點並選取目的地。
- 未被劇情揭露的地點不會以灰色名稱或輔助文字提前洩漏。

因此 Chapter 2 開場不得再次用完整 tutorial 解釋「怎樣打開地圖、怎樣點圖釘、怎樣查看目的說明」。本章只教授 Chapter 1 沒有出現的新規則：

1. 同一階段可以同時有多個可前往地點。
2. Phase A／B／C 會讓澀谷地點群逐步擴張。
3. 地點調查順序可自由，但證據板與 proof order 不可跳步。
4. 主線必經與可選支線必須有清楚視覺差異；可選地點不得藏唯一必要證物。

產品梯度固定為：

> **Chapter 1 教玩家怎樣在東京移動；Chapter 2 才讓玩家決定下一步要去哪裡。**

### 19.2 固定東京拓撲與澀谷地點群

城市地圖不是每章重畫的新選單。全篇沿用同一份敘事拓撲；比例可以服務可讀性，但既有廣域錨點的相對方向不得任意改動。

```text
吉祥寺案件區 ─── 相馬事務所／中央據點 ─── KAGAMI 審查設施
                         │
                       澀谷
```

固定規則：

- Chapter 1 已建立的相馬事務所、雨鐘咖啡館、KAGAMI 審查設施與吉祥寺案件區節點保留原位置。
- Chapter 1 未揭露澀谷時，不顯示可讀圖釘或鎖定名稱；最多只保留無標籤的城市輪廓。
- Chapter 2 進入案件後，既有廣域「澀谷」錨點展開成第 7 節的 Phase A／B／C 地點群。
- 澀谷地點群可在同一地圖上以局部放大或 cluster 呈現，但不能另建第二份不一致的東京世界狀態。
- 後續章節增加新區域時，只能擴張現有拓撲，不得為了畫面構圖移動既有節點。

### 19.3 Phase A／B／C 的新 onboarding 定位

| 階段 | 地圖教學責任 | 保留的案件責任 |
|---|---|---|
| Phase A | 第一次讓多個目的地同時可互動；用首批五個核心地點教玩家自行選順序 | 約 20 分鐘內完成「粉絲手機其實拍到牆」的小翻面 |
| Phase B | 教玩家地圖會因新事實擴張，並把新地點加入既有澀谷群 | 完成視線板與畫面板 |
| Phase C | 教玩家主線與可選節點的清楚差異；不再增加新的地圖基本操作 | 完成路線板、人物板與強制青葉公開資料核驗 |

Phase A 首次打開多目的地地圖時，只需一句簡短提示，例如：

> 「目前有多個可調查地點。順序由你決定。」

不要重播 Chapter 1 的單一目的地 onboarding，也不要讓地圖教學壓過案件冷開場。

### 19.4 自由順序與 proof order 的硬邊界

- 玩家可以先查三枝、粉絲、控制室、外送員或真白房間，但不能在完成視線板／畫面板前把維修路線當成已證事實。
- Phase C 的可選支線只補人味、伏筆與額外審查會台詞；所有主線必需資訊維持第 7～14 節既有備援來源。
- 任一主線事實都不能只存在於一個可錯過圖釘。
- 地圖自由只改變取得順序與證據重讀味道，不改變七段審查會 proof order。
- 青葉公開資料核驗仍是 Phase C 必經，不得因地圖自由度而被做成可錯過支線。

### 19.5 故事狀態與呈現邊界

故事層只需要描述可見、可前往、目前所在與已完成的地點語意；程式實作必須沿用 investigation sublocation 的既有 lock／visibility／current／completion 狀態，不建立第二份地圖進度。

地圖 presentation 可以擁有：

- 固定節點座標。
- 地點 label／icon。
- 當前目的說明。
- Phase／cluster 顯示分組。
- 主線／可選的視覺呈現。

地圖不得另外擁有：

- 第二份 durable unlock collection。
- 第二份 current location。
- 第二份 visited／completed progress。
- 行動點、交通費、時間成本或錯過事件。

### 19.6 本章地圖非目標

本章仍不包含：

- 大型開放世界。
- 自由步行或列車操作。
- 路徑搜尋、路線動畫、交通模擬。
- 地圖完成率、收集物或秘密圖釘。
- 為每個 Phase 建立互不相干的新地圖。
- 因地圖導入而新增第五塊兇案證據板或改寫蓮見動機。

### 19.7 更新後的成功標準

- Chapter 2 第一張可操作地圖即能同時呈現多個目的地，證明它是 Chapter 1 線性導航的自然升級。
- 玩家不需要重新學基本點選操作，只需要理解「現在可以自行選順序」。
- Phase A／B／C 在同一澀谷地點群上逐步擴張。
- Chapter 1 已建立的城市錨點仍保持相同位置與身份。
- 地圖順序自由不改變四塊證據板、七段 proof order、青葉核驗必經性或任何兇案定錘。
