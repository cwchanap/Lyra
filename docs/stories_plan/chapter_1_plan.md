## 0. 使用方式

Writer agent 不要把本文件寫成小說正文。它是每個 beat 的「施工圖」。

每一 beat 需要產出以下內容：

1. **Scene List**：這個 beat 拆成幾個 scene，每個 scene 的地點、角色、目的。
2. **Scene Draft**：主要對話與情緒流。
3. **Interaction Script**：玩家可調查、可出示、可選錯的點。
4. **Evidence Update**：正式證物欄、人物筆記、背景符號各有哪些變化。
5. **Exit Condition**：玩家完成什麼理解後，才能進下一 beat。

本章的寫作目標不是把所有邏輯都用台詞講清楚，而是讓玩家透過場景、操作、視線、物件與審查會選擇，自己走到結論。

### V3.9 時長與 high-level 同步策略

V3.7 / V6.5 canon patch 曾將第 1 章鎖在 2.5～3 小時；V3.9 因採納正式 opening atmosphere block，**第 1 章 high-level 時長需要同步放寬**。

建議目標：

| 版本 | 建議體感 |
|---|---|
| 標準流程 | 約 3～3.5 小時 |
| 若保留完整 prologue 互動與日常支線 | 可接近 3.5～4 小時 |

High-level 調整建議：若本版成為 master，Story Bible / canon sync patch 中第 1 章時長應由「2.5～3 小時」更新為「標準 3～3.5 小時；完整互動版 3.5～4 小時」。這不是主案變複雜，而是正式加入序章生活感。

限制不是總時長，而是節奏：

- KAGAMI summary 冷開場建議在開局 25～35 分鐘內落地；若 Prologue 互動完整保留，最晚不要超過 40 分鐘。
- Prologue 不得變成獨立案件長篇。
- Prologue 伏筆不得搶主案 proof order。
- 主案核心仍需乾淨、可回推、fair-play。

## V3.9 Opening Atmosphere Patch 鎖定

本版在 V1.2 最終施工圖與 V3.8 opening patch 基礎上鎖定以下內容：

1. **Prologue 0：雨中的東京** — 建立 KAGAMI 作為日常基礎設施，而不是一開始就邪惡的系統。
2. **Prologue 1：零號小委託 / 重印收據** — 用低風險小糾紛教玩家「真紀錄也可能被讀錯意義」。
3. **Prologue 2：雨鐘咖啡館的普通日** — 在三宅成為嫌疑人、增田成為死者前，先讓他們作為普通人出現。
4. **序章伏筆邊界表** — 允許放入藍色透明傘色彩記憶、金木犀、紙本收據、舊掛鐘、閉店 SOP、末班車提醒等，但不能讓它們成為第 1 章正式證物。
5. **時間策略放寬** — 第 1 章可比 V3.7 更長，但不得拖延到玩家失去案件鉤子。
6. **主題先行但不說破** — Prologue 只讓玩家體驗「資料的意思可能被讀錯」，不要讓角色提前說出門鎖主詭計答案。
7. **KAGAMI 範圍同步** — Prologue 可以呈現 KAGAMI / 類 KAGAMI 摘要作為試點區、合作企業與高壓資料流程中的第一閱讀入口，但不能讓它看起來像全東京所有日常糾紛的唯一系統。
8. **Prologue 練習證物隔離** — 零號小委託的收據、帳本、監視器等只能進「練習欄 / Prologue Notebook」，完成後自動歸檔，不能在主案證物欄出現。
9. **序章 SOP 降明示** — Prologue 可以種下閉店流程與 backflush 噪音，但精確的 22:50 / 22:52 時間鎖必須留到 Beat 3 主案正式調查。

## 1. 全章前台證據包

第 1 章雖然有多個證物，但前台只能讓玩家記住三個大問題。Writer agent 在每一 beat 都要確認當前內容服務哪個證據包。

| 證據包 | 玩家要理解的命題 | 主要 beat |
|---|---|---|
| 三宅小謊包 | 三宅說謊，但不是因為殺人 | Beat 2、4、5、8.5、10 |
| 第三者動線包 | 有人比三宅更早從承包商動線進入後場 | Beat 3、7、8、8.5、9 |
| 門鎖時序包 | 門鎖沒有說謊，但 summary 把合併時間當成事件時間 | Beat 0、5、8、8.5、10 |

寫作上不要讓玩家一次背二十個證物名稱。每次互動只問一個小問題：

- 三宅為什麼說謊？
- 三宅站的位置看得到屍體嗎？
- 有沒有第三者？
- 那個第三者走的是哪條動線？
- 門鎖上的時間到底是什麼時間？
- 誰最符合那個空位？

角色對白只用這三個口語詞：

| 口語詞 | 意義 |
|---|---|
| 摘要 | KAGAMI summary，警方與審查會先看到的整理後故事 |

# Prologue Block：普通世界被 summary 打碎之前

## Prologue Block 功能

V3.8 在 Beat 0 之前新增一個正式序章區塊。這不是前傳，也不是新案件；它的功能是讓玩家先看見「普通的東京、普通的委託、普通的咖啡館」，再進入 KAGAMI summary 的冷硬敘事。

核心效果：

> 玩家不是先看到「嫌疑人三宅」。  
> 玩家先看到一個會帶蛋糕邊回家的兼職、一個會收紙本收據的律師、一個常點金木犀拿鐵的上班族、一個習慣相信摘要的城市。  
> 然後 summary 才把他們壓成一行結論。

## Prologue 使用規則

| 規則 | 說明 |
|---|---|
| 不新增正式證物 | Prologue 中看見的東西最多成為情感記憶；若後面要作證物，必須在主案調查中重新取得 |
| 不改案發時間線 | Prologue 不能提供案發夜不在場證明，也不能讓相馬案前成為目擊者 |
| 不提前解碼伏筆 | 藍傘、金木犀、90 秒、`ZW_A16.lock`、雨宮、A-90、青葉都不能在 Prologue 說破 |
| 不讓小委託破壞主案驚喜 | 零號小委託只教「紀錄意義可能被讀錯」，不能用門鎖、同步、合併時間、KAGAMI summary 作題材 |
| 不讓雨鐘普通日變成證物片段 | 雨鐘普通日最好標示「數日前」或用 cinematic 呈現；不能有精確案發夜時間 |
| KAGAMI summary 仍要早出現 | Prologue 可以慢，但案件鉤子建議在開局 25～35 分鐘內落地；完整版最晚不要超過 40 分鐘 |

# Prologue 0：雨中的東京 — KAGAMI 作為日常背景

## Beat 功能

建立現代東京的基礎氣氛：潮濕、忙碌、便利、相信摘要。KAGAMI 不是邪惡魔王，也不是神秘黑箱；它是司法試點區、警方 / 檢方 / 律師與合作企業資料鏈中常被先看到的「第一閱讀入口」，不是全東京日常生活的萬能裁決 app。

這段讓玩家理解：

> 這座城市不是因為 KAGAMI 存在才壞掉。  
> 這座城市在某些試點與合作流程裡，因為摘要太方便，所以太快相信被整理好的第一個故事。

## 建議時長

3～5 分鐘。

## 場景單位

### Scene P0A：雨中的電車站

地點：吉祥寺 / 新宿 / 涉谷沿線電車站，可用 montage。  
角色：無主角或只用遠景人群。  
目的：讓玩家看見「摘要化」已是東京的日常語言，但不要把 KAGAMI 寫成所有日常服務。

畫面元素：

- 電車站螢幕顯示普通城市交通摘要：延誤原因 / 影響路線 / 替代路線。這是一般城市 UI，不必標 KAGAMI。
- 旁邊新聞螢幕播出短訊：`KAGAMI Evidence Summary Pilot：證據摘要審查會擴大試行。`
- 一名上班族只看了新聞標題，就說：「又是那個證據摘要系統。」
- 商店街雨棚下，有人說：「新聞說現在連證據都能先整理好。」
- 另一人回：「也好吧。總比誰聲音大誰贏。」

不要讓任何人說：「可是摘要也會錯。」這句太早。也不要讓普通市民直接操作 KAGAMI。

### Scene P0B：雨傘與反光

地點：街頭人行橫道。  
角色：人群。  
目的：建立雨、透明傘、反光、看錯的視覺語言。

畫面元素：

- 透明傘群在紅綠燈下交錯。
- 巨型螢幕字幕倒映在傘面上。
- 某幾把透明傘被藍色招牌反光染成一瞬間的淡藍，不是一把固定的藍傘。
- 金木犀花壇或香氛廣告只是一秒背景。

Writer note：這不是「藍色透明傘正式登場」。它只是長線色彩記憶，不能讓玩家或角色注意。不要拍成可追蹤道具。

### Scene P0C：城市相信第一份摘要

地點：法律諮詢所外 / 商店街電子看板。  
目的：把「摘要替人做第一判斷」自然化。

可以用一個小剪影：

- 法律諮詢所外的螢幕播放「證據摘要審查會」宣傳短片。
- 旁邊路人只看標題就判斷：「有系統整理，應該比較不會冤枉人吧。」
- 另一人沒有反駁，只撐傘離開。
- 畫面不判斷誰對誰錯，只呈現社會對 summary 的信任與期待。

## 玩家此時應理解

- KAGAMI 是司法 / 城市證據試點中被社會熟知的制度，不是突兀科幻設定，也不是一般消費 app。
- 東京人習慣先看整理後版本，但這不代表所有事情都由 KAGAMI 裁決。
- 雨、反光、透明遮蔽物會是本章視覺語言。

## 不要做

- 不要出現相馬童年、青葉、A-90、第零證人。
- 不要讓 KAGAMI 畫面故障。
- 不要把淡藍傘拍成道具。
- 不要用旁白說主題。

## Exit Condition

玩家帶著「這座城市習慣相信摘要」的感覺，進入相馬的低風險小委託。

# Prologue 1：零號小委託 — 重印收據

## Beat 功能

用一個 6～10 分鐘的小糾紛完成三件事：

1. 教玩家最基本的調查 / 出示 / 比對操作。
2. 建立相馬會認真處理小事，且相信證據能保護普通人。
3. 以生活層級預演本章主題：**紀錄是真的，但它記下的可能不是你以為的那個時間。**

這段不是正式案件，不需要審查會，不進主案證物欄。若遊戲需要教學 inventory，請使用「練習欄 / Prologue Notebook」，完成後自動歸檔。

## 建議時長

6～10 分鐘。

## 小委託設定

地點：相馬事務所附近的文具店 / 影印店。  
委託人：文具店店主。  
被誤會者：高中生 / 大學生客人。  
早坂：不要寫成純巧合路過。建議她是來取相馬上一份小型 evidence review 意見書 / 領收據，剛好看見這個小委託收尾，不需要主導。

表面問題：

- 店主認為學生沒有付影印費。
- 收據顯示付款時間是 17:42。
- 監視器顯示學生 17:38 已離開。
- 店主認為學生先拿走影印資料，後來才有人補印收據，所以學生說謊。

真相：

- 收銀機當時卡紙。
- 店主在 17:42 **重印**收據給自己留帳。
- 17:42 是「重印時間」，不是「付款時間」。
- 學生有付錢，店主也沒有造假；只是大家把收據時間讀成了付款時間。

## 場景單位

### Scene P1A：小店糾紛

玩家第一次看到相馬工作。

相馬不急著指責任何人。他先問：

- 收據是原印還是重印？
- 收銀機今天有沒有卡過？
- 監視器上的學生手裡有沒有拿找零？
- 店主的帳本是手寫還是自動同步？

### Scene P1B：基本調查教學

此處使用練習欄，不使用主案證物欄。可調查點：

| 調查點 | 發現 | 教學功能 |
|---|---|---|
| 收據 | 右下角有 `REPRINT` 小字 | 真文件也要看生成方式 |
| 收銀機 | 卡紙處有撕裂紙屑 | 物件調查 |
| 監視器 | 學生離開前，店主低頭找零 | 畫面不是單靠時間看 |
| 手寫帳本 | 17:37 有一筆影印收入 | 紙本資料與電子資料互補 |

### Scene P1C：出示證物教學

玩家可選錯：

- 只出示監視器：店主反駁「他離開了，但收據在後面」。
- 只出示收據：學生看起來更可疑。
- 正確組合：收據 `REPRINT` + 收銀機卡紙痕 + 手寫帳本。

相馬結論：

> 「這張收據是真的。」  
> 學生的臉白了一下。  
> 相馬接著說：  
> 「但它記下的是重印時間，不是付款時間。」

### Scene P1D：早坂紙本收據種子

事件結束後，早坂把那張重印收據影本貼進筆記。

相馬：「你連這種小事都留？」  
早坂：「小事才最容易被當成沒必要留。」

不要讓她長篇講保全鏈。

## 可放的伏筆

| 伏筆 | 呈現方式 | 邊界 |
|---|---|---|

## F6. 地圖狀態與可見資訊

Chapter 1 只需要玩家能理解的三種呈現：

| 狀態 | 顯示 | 互動 |
|---|---|---|
| 可前往 | 唯一目的地高亮，顯示本次目的 | 可選 |
| 已到訪 | 可低對比保留，建立空間記憶 | 不可選 |
| 未揭露 | 不顯示圖釘、名稱、輔助文字或焦點項 | 不可選 |

硬規則：

1. 任一 Chapter 1 地圖畫面恰好只有一個可互動圖釘。
2. 已到訪地點不可因 disabled 樣式仍接受滑鼠、鍵盤或手掣事件。
3. 未揭露地點不可透過 DOM label、讀屏文字、圖例或焦點順序洩漏。
4. 雨鐘與 KAGAMI 再次開放時沿用原座標，更新目的文案並重新成為唯一可互動圖釘。
5. 選取唯一目的地後直接進下一 scene，不出現錯誤選擇或二次確認。
6. Save／Continue 必須回到同一待選地圖步驟或已進入的下一 scene，不重播一次性 reveal。

推薦文案：

- `新的調查地點已確認`
- `前往下一個地點`
- `前往：雨鐘咖啡館`

禁止文案：

- `選擇下一個調查地點`
- `你要先去哪裡？`
- `剩餘行動次數`

## F7. Scene authoring 施工邊界

地圖是現有 scene 間的薄轉場，不把 Chapter 1 合併成大型 investigation scene。

Authoring pass 應：

- 在 F3 九個跨場所邊界插入 map-navigation interstitial。
- 保留原 scene 的對話、證物 reveal、fact、question、objective、authorization 與 proof order。
- 每個 interstitial 只承擔一句目的說明、唯一目的地選取與下一 scene 進入。
- Interstitial 不取得證物、不斷言 story fact、不解鎖青葉內容、不發雨宮訊息、不承擔案件推理。
- `Scene 11A／11B → Scene 11C／11D` 可在自然地點邊界拆 scene，只為插入第九次導航；不得改寫 USB、雨宮來源排除或藍傘空鏡內容。
- Prologue 普通日不因地圖導入變成可返回地點或支線 hub。

## F8. 程式與故事狀態邊界

故事層只定義目的地身份、穩定座標、可見語意與本次目的。程式實作必須沿用 investigation sublocation 的既有 lock／visibility／current／completion 狀態，不建立第二份 durable map progress。

地圖 presentation 可擁有：

- 固定節點座標。
- label／icon。
- 本次目的說明。
- Chapter／Phase 顯示分組。

地圖不得另有：

- 第二份 unlock／visited／completed collection。
- 第二份 current location。
- 新 scene type 或第二套 navigation state machine。
- 行動點、交通費、時間流逝、路徑搜尋或交通模擬。

Chapter 1 第一個 code slice 只需讓真實九段路線可玩，並確保同一表示法未把「單一目的地」寫死，使 Chapter 2 能同時呈現多個可用目的地。

## F9. 對既有附錄的覆寫

- 附錄 A 中 F3 的九個跨故事場所轉場改由城市地圖觸發；表內其餘同場所轉場保持自動。
- 附錄 C 的最短通關理解不變；地圖不新增案件命題，只讓玩家親自完成移動。
- 附錄 E 的青葉提問契約不變；第九次導航只把玩家送回相馬事務所，不得把青葉與 `ZW_A16.lock` 同框。
- Chapter 1 時長仍以 V3.9 為準；九次地圖操作應保持短促，不加入重複長對話。
